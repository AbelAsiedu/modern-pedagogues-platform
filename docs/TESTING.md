# Testing

- `npm run test:unit` - pure logic (money, permissions, tokens, passwords, validation, env, errors, logger redaction). No database.
- `npm run test:integration` - real PostgreSQL, no mocks. Global setup drops and recreates the `public` schema of `TEST_DATABASE_URL` (the database name must end in `_test`) and applies every migration, so each run also proves migrations work from empty. Covers auth flows, sessions, rate limiter atomicity, audit immutability, constraints and seed idempotency.
- Test-only: the harness disables the audit triggers inside a transaction to wipe tables between tests; a test proves they are re-enabled.
- Also covered: site-text saving/permissions/atomicity, the rich-text renderer, tutor applications and review workflow (including a concurrent-decision race and privacy of the public shape), Kaitlyn's guard, provider request/response handling (with a fake `fetch`), answer pipeline, rate limits, knowledge/prompt contents, and admin permissions.
- Also covered: image processing (formats, resize, EXIF removal, appended scripts, SVG/GIF refused), the media library and its permissions, tutor photo paths, product and price rules, PDF checking, publishing rules, the order and payment-confirmation flow (idempotency, double clicks, concurrent confirmation, who may download), and the Kaitlyn connection test.
- Also covered (stage 5): business-detail validation and token flow, menu/SEO/curricula editing, picture replacement (moves banners and tutor photos, removes the old picture, refuses non-staff), the admin overview limited by role, phone-number handling, and testimonial parsing.
- Also covered (marketplace): PDF inspection (readable, encrypted, scripts, page count), the quality rubric and readiness checklist, creator joining, ownership of listings and covers, price floors and level lists, contact-detail refusal (without rejecting years such as 2019-2023), the submit/review/approve/changes/decline lifecycle, rubric gates, the lost-update and concurrent-reviewer guards, replacing an approved file, hiding/showing, take-down and restore, free downloads and their count, paid files staying locked, the 70/30 split fixed at payment, payout limits (including two at once), and creator suspension.
- Not covered yet: automated browser/E2E tests, payment webhooks (none exist yet), malware scanning. No test calls a real AI provider.

Latest: 412 tests (unit + integration) pass; lint, typecheck and production build pass. Two-step sign-in: 22 unit tests (the RFC 6238 test vectors, replay and window rules, recovery-code parsing, encryption round-trip and tamper cases, the QR generator's structure) and 27 integration tests (set-up, confirmation, single-use tickets, replay and simultaneous-attempt refusal, five-wrong-codes lockout, ticket expiry, recovery codes with a lost key, disable/regenerate/reset, and the staff requirement in `validateSession`). A Playwright run against the production build covered the whole web flow in 27 checks (staff sent to set-up and the admin area and staff API refused until it is done; the QR code decoded with an independent reader and matches the on-page key; wrong and replayed codes refused; the ticket cookie HttpOnly and gone after sign-in; recovery codes accepted once; five wrong tries burn the ticket; turning it off with the password and a recovery code; the owner's `admin:reset-mfa` command; no sideways scrolling on a phone; no console errors). That script is not in the repo, so it is not an automated regression test. The real Heroku backup and restore commands have not been run from here (the Heroku CLI is not available); `scripts/backup-download.sh` was run against a stand-in `heroku` command that produced a real PostgreSQL dump, and the restore commands in BACKUPS.md were run against a local database. Manual browser runs (adding a resource in one step, publish/hide, download of a free PDF, a refused PDF and a refused publish without a PDF: 14 checks; the redesign and picture slots: 55 checks (the subject filter and quick links, favicon, share picture, service card and About story pictures included) on desktop and phone with sample pictures uploaded through the admin page and API: slots, logo, reset to illustration, unknown-slot and anonymous uploads refused, no broken images or sideways scrolling on nine pages, mobile menu, no console errors); earlier runs (Playwright against the production build; scripts are not in the repo, so they are not automated regression tests) covered: **the marketplace end to end in 60 steps** (creator joins, uploads a cover and PDFs, is refused a fake or too-short PDF, submits; the reviewer is refused an approval with missing scores, a failing gate or a low average, asks for changes, then approves; public listing, filters and locked paid file; order, payment confirmation, the 70/30 split, download; payouts that cannot exceed the balance; a free resource; take-down and restore; creators kept out of staff pages); sign-in and cookie flags, banners and the slideshow; the site-text editor (edit, reset, `<script>` and `javascript:` links in a policy, audit entries); a full tutor flow (application with rejected contact details, staff review, incomplete-profile approval refused, approval, public page with no private data leaking, filters, hide); and Kaitlyn (widget open/close/Escape/focus, bullets and links rendered, injected `<script>` not executed, blocked and fallback replies, the API refusing missing/foreign Origin and bad content types, admin knowledge reaching the prompt, the kill switch hiding the widget).
